# ⚠️ Убрать перед запуском

Единый список **всех временных вставок**, сделанных ради того, чтобы функции
можно было посмотреть глазами до появления настоящих пользователей.

Пока этот файл не пуст, сайт не готов к боевой работе.

Нумерация та же, что в разделе [«Временные демо-вставки»](README.md#временные-демо-вставки)
README: там — как каждая устроена, здесь — что и в каком порядке убирать.

Найти всё в коде разом:

```bash
grep -rn "ВРЕМЕНН" src scripts migrations
```

Каждая вставка помечена там значком ⚠️ и словами «ВРЕМЕННАЯ ДЕМО-ВСТАВКА»
или «ВРЕМЕННОЕ ТЕСТОВОЕ ПОСЛАБЛЕНИЕ».

## 1. Демо-данные

**Что:** 7 бригад, 16 заказчиков, модератор, 7 человек в очереди на
модерацию, 3 менеджера поставщиков, 120 отзывов о товарах и 34 о бригадах.

**Файлы:** `scripts/seed-demo.ts`, `scripts/deploy-seed.ts`,
`migrations/0016_demo_seed_state.sql`

**Заводятся сами.** Шаг `npm run db:seed:deploy` встроен в `vercel-build` и
на первом боевом деплое заполняет базу без единой команды с чьей-либо
стороны. Повторно он не срабатывает: факт засева записан строкой в таблице
`demo_seed_state`. Подробности — в README, раздел «Демо-данные заводятся тем
же деплоем».

**Убрать:**

```bash
npm run demo:seed -- --clean
```

Скрипт удаляет всё, что завёл: находит по почте `@demo.opusgroup` и по метке
`[демо]` в текстах отзывов. Подпись «демо-данные» рядом с блоком отзывов
вычисляется по автору, поэтому исчезает сама вместе с данными — убирать её
руками не нужно.

Отметку в `demo_seed_state` уборка намеренно **оставляет** — именно она не
даёт следующему деплою завести всё обратно. Поэтому убирать данные можно и
до того, как выкинут сам шаг деплоя: порядок значения не имеет. Если нужно
остановить засев прямо сейчас, не трогая код, — `SKIP_DEPLOY_SEED=1` в
переменных Vercel.

**Удалить насовсем:** `scripts/seed-demo.ts`, `scripts/deploy-seed.ts`,
строки `demo:seed` / `db:seed:deploy` в `package.json` и звено
`npm run db:seed:deploy &&` из `vercel-build`. Таблицу `demo_seed_state`
можно оставить: она пустая по смыслу и ни на что не влияет.

## 2. 🔴 Переключатель роли и тестовый доступ к модерации

**Что:** маршрут `POST /api/demo/role` меняет роль текущего пользователя на
`client`, `executor` или `moderator`; плашка с кнопками в кабинете; готовая
учётная запись `moderator@demo.opusgroup`.

**Чем это плохо:** любой вошедший делает себя модератором.

**Выключить:** `DEMO_MODE=false`. Без флага маршрут отвечает 404, а не 403 —
по ответу не должно быть видно, что где-то есть выключенная возможность
повысить себе права.

**Удалить насовсем:** `src/app/api/demo/role/`,
`src/components/demo/DemoRoleSwitch.tsx`, два импорта и строка JSX в
`src/app/cabinet/page.tsx`.

## 3. ⚪ Плашка остатка бесплатного тарифа

**Что:** «Бесплатно: 1 из 1 использовано» в кабинете исполнителя.

Помечена временной по просьбе, но **временного в ней ничего нет**: числа
настоящие, из того же кода, что и серверная проверка лимита. Смысл её в том,
чтобы отказ не был неожиданностью — без неё человек узнаёт о лимите после
того, как написал текст отклика и нажал «Отправить».

Удалять стоит только вместе с заменой на что-то лучшее.

**Файлы:** `src/app/cabinet/FreeQuotaNote.tsx`, `renderFreeQuota` в
`src/app/cabinet/page.tsx`.

## 4. 🔴 Ослабленное правило отзывов — самое опасное

**Что снято** (миграция `0010_reviews_demo_relax.sql`):

| Настоящее правило | Что действует сейчас |
|---|---|
| отзыв только по **своей завершённой заявке** | отзыв от любого вошедшего о любом исполнителе |
| один отзыв **на заявку** | один отзыв **от человека об исполнителе** |
| `request_id` обязателен | может быть пустым |

**Чем это плохо:** рейтинг перестаёт быть свидетельством. Любой
зарегистрировавшийся может поставить конкуренту единицу, ни разу с ним не
работав, — а по этому рейтингу заказчик выбирает, кому доверить крышу.

**Флагом не закрывается.** Это схема базы.

**Как вернуть:** полный SQL написан комментарием в шапке
`migrations/0010_reviews_demo_relax.sql`. Скопировать в новый файл
`migrations/00NN_reviews_strict.sql` *(номер — следующий свободный)* и
применить `npm run db:migrate`. Функция `reviews_check_eligibility()`
намеренно не удалялась — правило вернётся ровно таким, каким было.

**Заодно удалить:**

- `src/app/api/executors/[id]/review/` — маршрут отзыва без заявки;
- `createReviewForExecutorDEMO` в `src/lib/server/reviews/queries.ts`;
- `src/components/demo/DemoReviewForm.tsx` и две строки в
  `src/components/pages/ExecutorList.tsx`.

## 5. 🔴 Переключатель «Посетитель / Модератор» в углу

**Что:** плашка снизу слева на любой странице, переключает роль на лету. Тот
же маршрут, что в пункте 2, — и та же дыра.

**Файлы:** `src/components/demo/DemoModeCorner.tsx`, две строки в

**Выключить:** `DEMO_MODE=false` — плашка не попадает даже в разметку.

## 6. 🟢 Чат с демо-менеджерами из карточки товара

**Что:** кнопка «Написать менеджеру» на странице товара открывает переписку с
выдуманным менеджером поставщика.

**Важно: правило «переписка только внутри заявки» при этом не ослаблено.**
Маршрут заводит настоящую заявку «Вопрос по товару …» с принятым откликом
менеджера, и дальше работает тот же чат с теми же проверками и тем же
триггером в базе. Ни одна проверка не снята — поэтому пункт и помечен низкой
опасностью.

Цена решения: в кабинете появляются заявки, которых человек не создавал. Они
уходят вместе с демо-данными.

**Файлы:** `src/app/api/demo/manager-chat/`, `src/app/api/demo/managers/`,
`src/components/demo/DemoManagerChat.tsx`, две строки в
`src/components/market/ProductDetail.tsx`.

**Выключить:** `DEMO_MODE=false`.

## Общее для пунктов 2, 5 и 6

Все три висят на одном выключателе. Когда дойдёт до уборки — удалять вместе:

- `src/lib/demo-mode.ts`
- `src/app/api/demo/` целиком
- `src/components/demo/` целиком *(там же лежит и форма отзыва из п. 4)*
- `DEMO_MODE` в `.env.example`

## Что при этом пропадёт из демонстрации

Стоит знать заранее, чтобы не искать «сломалось ли»:

- витрина бригад и магазин станут пустыми — настоящих исполнителей и отзывов
  пока нет;
- на «Услугах» вместо бригад появятся пять образцов-заглушек без рейтинга,
  это штатное поведение;
- экран модерации покажет пустой список.

## Проверка перед запуском

```bash
npm run demo:seed -- --clean          # 1: демо-данные убраны
grep -n db:seed:deploy package.json   # 1: звена в vercel-build больше нет
grep -rn "ВРЕМЕНН" src scripts        # 2–6: ничего не найдено
grep -n DEMO_MODE .env                # 2, 5, 6: false или строки нет
npm run db:migrate:status             # 4: 00NN_reviews_strict применена
npm run build                         # сборка зелёная
```
